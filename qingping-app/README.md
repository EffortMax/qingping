# 清屏 QingPing v1.0

自动跳过其他 APP 开屏广告、防误触跳转，按 APP 统计拦截次数。

> 核心原理：无障碍服务（AccessibilityService）识别“跳过”并自动点击。
> 这是目前非 Root 下唯一稳定可用的方案（李跳跳、叮小跳等同类 APP 均用此方案）。

---

## 1. 安卓下实现拦截所需的权限和限制

### 1.1 必须的权限/能力

| 权限/能力 | 用途 | 是否必须 | 说明 |
|---|---|---|---|
| 无障碍服务 BIND_ACCESSIBILITY_SERVICE | 读取其他 APP 界面节点、执行点击/返回手势 | ✅ 必须 | 核心。需用户在系统设置中手动开启，代码无法代开。服务运行在系统进程调度中，清理后台杀不掉它 |
| RECEIVE_BOOT_COMPLETED | 开机自启 | ✅ 必须 | 安装后需用户手动打开过一次 APP 才会生效；国产 ROM 还需在“自启动管理”中手动允许 |
| FOREGROUND_SERVICE + 前台通知 | 保活 | ✅ 必须 | Android 8+ 后台运行必须弹常驻通知，否则进程很快被杀 |
| POST_NOTIFICATIONS | 显示前台通知 | Android 13+ 必须动态申请 | 不给则前台服务通知发不出，保活降级 |
| REQUEST_IGNORE_BATTERY_OPTIMIZATIONS | 电池白名单 | 强烈建议 | 引导用户加白名单，减少被省电策略杀死；但 OEM 仍可能无视 |
| QUERY_ALL_PACKAGES | 展示统计列表的应用名/图标 | 建议 | Android 11+ 按包名查应用信息需要；上架 Play 审核极严，建议走官网渠道 |
| canPerformGestures 手势 | 点击“不可点击的纯文本跳过” | 需要（minSdk 24+） | 本项目 minSdk=24，原生支持 |

### 1.2 系统限制（做不到的事，先说清楚）

1. **不能真正“拦截广告请求”**：非 Root 拿不到其他 APP 的网络请求，只能做到“广告出现后 100~300ms 内自动点跳过”。视觉上接近无广告，但广告实际加载过。
2. **图片型/异形跳过按钮可能漏过**：纯图片无文字的“×”、极小的关闭区、需要滑动的广告，只能部分覆盖。本方案用“关键词 + 手势点中心 + 小面积优先”三重策略，已是文本方案的天花板；要 100% 需配合截图 OCR（耗电且需额外权限，v1 未做）。
3. **摇一摇/扭手机广告防不住“触发瞬间”**：这类靠传感器触发，只能做“跳转后的兜底返回”（本方案已做），不能阻止传感器事件。彻底防需用户去系统设置关掉问题 APP 的“获取设备动作与方向”权限。
4. **清理后台 vs 无障碍**：清理后台杀的是清屏自己的进程，无障碍跳过不受影响。但部分 OEM（一加/华为省电模式）会在清理时连带“冻结无障碍”，需引导用户锁定后台 + 加白名单。
5. **开机自启不保证 100%**：`BOOT_COMPLETED` 受“安装后需手动打开一次 + OEM 自启动管理”双重限制；无障碍服务本身由系统在开机后自动恢复（不需要本 APP 拉起），前台通知则需要广播拉起，Android 10+ 后台启动限制下偶发失败，下次打开 APP 会恢复。
6. **Android 13+ 受限制设置**：旁加载 APK 安装后，系统可能禁止直接开无障碍，需用户去“应用信息 → 右上角 ⋮ → 允许受限制的设置”后才能开。这是系统安全机制，所有同类 APP 一样。
7. **不能上架 Google Play（严格意义）**：Play 对无障碍 + QUERY_ALL_PACKAGES 审核极严，“跳过广告”通常过不了无障碍声明。建议官网/蒲公英/应用宝等国内渠道分发。
8. **目标 APP 反制**：极少数 APP 检测到无障碍开启后不让用（如部分银行/游戏），用户需在清屏里关服务或用系统“无障碍快捷方式”临时切换，这是无解的对抗问题。

## 2. 能实际运行的方案（本工程已实现）

### 2.1 架构

```
系统事件 → SkipAccessibilityService（系统进程调度，杀不掉）
              ├─ TYPE_WINDOW_STATE_CHANGED / CONTENT_CHANGED
              ├─ 关键词扫描（跳过/Skip/关闭…，≤20字防误伤）
              ├─ 三级点击：节点点击 → 父节点点击 → 手势点中心
              ├─ 误触跳转兜底：3s内 A→B 切包则自动 BACK
              └─ Room 记录 → MainActivity 按 APP 展示统计
BootReceiver（开机）→ KeepAliveService（前台通知保活+自检）
```

### 2.2 功能清单：能实现 ✅ / 受限 ⚠️

| 功能 | 状态 | 说明 |
|---|---|---|
| 开屏“跳过”自动点击 | ✅ 已实现 | 关键词可配，100ms 级响应 |
| 按 APP 统计跳过次数并查看 | ✅ 已实现 | Room 本地库，APP 内列表+总数展示 |
| 误触跳转（跳浏览器/应用市场）自动返回+统计 | ✅ 已实现（实验性） | 启发式：3s 内切包即判跳转并 BACK，可在设置中关闭 |
| 开机后自动运行 | ✅ 已实现，⚠️ 受 OEM 限制 | 双保险：无障碍由系统自恢复 + BootReceiver 拉前台服务 |
| 清理后台后不失效 | ✅ 核心不失效 | 无障碍服务不怕清理；前台通知被杀后下次打开恢复 |
| 摇一摇广告的事前拦截 | ⚠️ 做不到，只能事后返回 | 系统限制，见 1.2-3 |
| 图片型跳过 100% 识别 | ⚠️ 部分覆盖 | v1 为纯文本方案；v2 可加模板/OCR |
| 无通知静默保活 | ❌ 做不到 | Android 8+ 强制要求前台通知 |

### 2.3 关键代码位置

- 跳过引擎：`app/src/main/java/com/qingping/app/service/SkipAccessibilityService.kt`
- 保活服务：`service/KeepAliveService.kt`
- 开机广播：`receiver/BootReceiver.kt`
- 统计（Room）：`data/StatEntity.kt, StatDao.kt, AppDatabase.kt, StatRepository.kt`
- 主界面：`ui/MainActivity.kt` + `res/layout/activity_main.xml`
- 无障碍配置：`res/xml/accessibility_service_config.xml`

## 3. 构建与运行

### 环境要求
- Android Studio Hedgehog (2023.1.1) 或更新
- JDK 11+，Android SDK Platform 34，Build-Tools 34
- 真机测试（模拟器无真实开屏广告，建议用带广告的国产 APP 测试）

### 步骤
1. 用 Android Studio 打开 `qingping` 文件夹（识别为 Gradle 项目），等待 Gradle Sync 完成；
2. 连接手机（开 USB 调试），点 ▶ Run，安装到手机；
3. 打开“清屏”，按提示依次开启：
   1. 无障碍服务（必开；Android 13+ 若提示受限制，先去应用信息右上角“允许受限制的设置”）；
   2. 电池白名单；
   3. 通知权限；
   4. 国产机去“自启动管理”允许清屏自启动，并把清屏卡片下滑锁定；
4. 打开任意有开屏广告的 APP（如微博、酷安、WPS），观察是否自动跳过；
5. 回到清屏首页查看按 APP 统计。

### 测试建议
- 开屏测试：冷启动目标 APP（先从后台划掉再开），连续测 5 次看成功率；
- 误触测试：开屏时故意点一下广告跳浏览器，看清屏是否 1 秒内自动返回并计数；
- 保活测试：把清屏从后台划掉，再开目标 APP，看是否仍能跳过（应仍有效）；
- 开机测试：重启手机（不开清屏），直接开目标 APP，看是否仍能跳过（无障碍自恢复则有效）。

## 4. 后续可迭代（v2 方向）
1. 悬浮窗“已跳过 N 次”实时提示（需 SYSTEM_ALERT_WINDOW）；
2. 按 APP 单独开关（黑白名单）；
3. 截图 + 本地 OCR 兜底图片型跳过（耗电明显，默认关闭）；
4. 规则云更新（需自建服务器+隐私合规说明）；
5. 导出/备份统计数据。
